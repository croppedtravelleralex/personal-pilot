# Personal Pilot 项目章程

## 项目愿景

Personal Pilot 是一个面向 Windows 11 桌面的多实例浏览器管理工具。长期目标是在一台本地设备上稳定管理多个彼此隔离的浏览器实例，并提供统一的实例切换、状态观察、代理绑定、内核管理和授权 API 操作能力。

当前新增方向是“应用内多实例真实浏览器窗口工作台”：在尽量保持每个浏览器实例指纹稳定和运行隔离的前提下，让用户能在同一个桌面应用窗口内无缝切换多个真实浏览器实例。

## 目标用户

- 需要在本地管理多个独立浏览器环境的个人或团队。
- 需要为每个实例绑定独立 profile、代理和启动参数的测试或运营场景。
- 需要通过本地授权 API 对已启动实例执行打开页面、查询状态、截图、录制或回放等操作的自动化场景。

## 最终完成态

- 桌面应用采用 Windows 11 专用栈：Tauri 2 + Vite + React + TypeScript。
- 每个浏览器实例仍由真实 Chromium/fingerprint-chromium 进程承载，保留独立 `user-data-dir`、代理、指纹参数和调试端口。
- 应用主窗口提供一个稳定的实例工作台：实例列表、标签切换、当前浏览器显示区、任务/API 操作区、状态和错误反馈。
- 视觉上浏览器在同一个应用窗口内切换；技术上不使用 WebView2 替代目标浏览器内核。
- 所有原生能力调用经过统一服务层，不让页面组件直接调用 Tauri 命令或系统能力。

## 成功标准

- 指纹稳定优先：除窗口尺寸、焦点、可见性等由嵌入显示天然引起的差异外，不应改变浏览器内核、profile、代理、UA、Client Hints、WebGL、Canvas、Audio、字体、语言、时区等核心环境。
- 实现可靠优先：窗口托管、切换、resize、focus、关闭、异常恢复可以反复执行，且不会造成实例状态漂移或残留不可控进程。
- 维护成本可控：Rust 只承担 native-only 能力，前端承担渲染和交互，业务状态放在 `features/`、hooks、store 和服务层。
- 性能符合 Win11 桌面工具基线：release 构建评估，应用冷启动、空闲 RSS、进程数、切换延迟和多实例调度均有验收记录。

## 明确不做

- 不使用 Electron。
- 不把目标网页改由 Tauri/WebView2 直接加载来冒充真实浏览器实例。
- 不把 headless + CDP screencast 作为最终“内嵌浏览器”方案。
- 不把多个浏览器实例合并到同一个 profile、同一个进程或共享状态中。
- 不新增 Node 后端服务、嵌入式 Python 运行时或多窗口嵌入式浏览器架构，除非用户明确批准。
- 不为了视觉效果牺牲指纹稳定、实例隔离和可恢复性。

## 长期质量底线

- 所有 native/system capability 调用统一从 `src/services/desktop.ts` 出口进入 Tauri。
- 大列表超过 200 条必须虚拟滚动；日志分页或增量加载；搜索默认 250-400ms debounce。
- 异步搜索、筛选、排序和任务调度必须有 stale-result 保护。
- 每个重要改动完成前必须通过结构合规、类型检查、release 构建和基线规则检查。
- 浏览器托管功能必须保留“外部窗口/预览模式”作为降级路径，不能把实验性 HWND 托管变成唯一可用入口。
