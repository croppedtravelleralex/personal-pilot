# 环境参数样板采集系统设计

> 本文档描述从真实浏览器运行时采集环境参数、建立**样板库 (Reference Library)** 的系统。
> 样板库为环境标识配置器提供"真实来源"的参数值，替代随机或硬编码的合成值。

---

## 0. 术语表

| 术语 | 含义 |
|------|------|
| 样板 (Reference Sample) | 从真实浏览器采集的一组完整环境参数快照 |
| 样板库 (Reference Library) | 多个样板的集合，按 OS/浏览器版本/地区 索引 |
| 采集器 (Collector) | 在浏览器中执行并采集参数的 JS/CDP 脚本 |
| 识别器 (Recognizer) | 将采集到的参数与已有样板匹配的算法 |

## 二、采集器 (Collector)

### 2.1 采集参数范围

| 参数族 | 采集方式 | 采集数 |
|--------|---------|--------|
| navigator.* | JS probe | 44 |
| Canvas 2D | toDataURL + getImageData | 38 |
| WebGL | getParameter + getExtension | 42 |
| Audio | AudioContext + AnalyserNode | 34 |
| 字体 | document.fonts.check | 34 |
| 媒体设备 | enumerateDevices | 30 |
| 屏幕/窗口 | screen.* + window.* | 28 |
| 时区/语言 | Intl + Date | 34 |
| 硬件 | navigator.hardwareConcurrency + deviceMemory | 18 |
| WebRTC | RTCPeerConnection | 36 |
| **总计** | | **~338** |

### 2.2 采集流程

```
1. 在目标环境中打开采集页 (chrome://version 空白页)
2. 按参数族分组执行 JS 探测
3. 标准化结果 (去 JS 类型 → 统一 JSON)
4. 添加元数据 (OS、浏览器版本、分辨率、时区)
5. 写入样板库

// 采集触发方式:
//   - 手动: 用户点击"采集"按钮
//   - 定时: 配置定时任务定期采集
//   - 自动: 每次 profile 启动时自动采集（配置启用后）
```

## 三、样板库 (Reference Library)

### 3.1 索引结构

```
reference_library/
├── windows-chrome-139/
│   ├── us-east-1920x1080.json
│   ├── us-west-1440x900.json
│   └── tw-taipei-1920x1080.json
├── windows-chrome-142/
│   └── ...
├── mac-chrome-142/
│   └── ...
└── index.json  (按 OS/浏览器版本/地区 索引)
```

### 3.2 分配策略

```
为 Profile 分配样板时:
  1. 匹配 OS + 浏览器版本
  2. 匹配目标出口地区 (country code)
  3. 匹配屏幕分辨率 (最接近)
  4. 如果无完全匹配 → 选择最接近的
  5. 如果无任何匹配 → 使用合成模板
```

## 四、识别器 (Recognizer)

比较新采集的样板与已有样板库的相似度：

```
相似度评分:
  - navigator.* 精确匹配: +1 分
  - Canvas 哈希值: 精确匹配 +5 分
  - WebGL vendor/renderer: 精确匹配 +3 分
  - Audio 特征向量: 余弦相似度 × 2 分
  
阈值: >85% = 同一浏览环境
      >60% = 高度相似
      <30% = 不同环境
```

## 五、使用场景

| 场景 | 说明 |
|------|------|
| 参数真实性提升 | 用真实样板替代随机合成值，减少统计学异常 |
| 环境指纹唯一性 | 基于样本人群分布分配参数，避免冲突 |
| 一致性基线 | 为一致性校验器提供"什么是正常"的参考依据 |
| 浏览器版本追踪 | 随浏览器版本更新自动切换参数基线 |
